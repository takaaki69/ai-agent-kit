# スケジュール・タスク管理の仕組み（全体像と使い方）

AI に「書記と見張り番」を任せて、予定とタスクを取りこぼさず、しかも**通知は絞って、埋もれさせない**ための仕組みです。
このファイルは仕組みの考え方と使い方の説明です。自分用の台帳の ID や実データは、このリポジトリには置きません（`LEDGER-PATTERN.md` 参照）。

## 何ができるか

- タスクと定例（毎月・毎週のやること）を、**1枚のスプレッドシート（台帳）** に集める。自分でいつでも開いて直せる。
- 予定は **Google カレンダー**に置く。
- AI がチャットの一言（「11/5 までに〇〇」）を台帳に書き、決まった時刻に台帳とカレンダーを見て、**短いまとめ**をスマホに届ける。
- 期日が近づくほど段階的に通知を強める。普段は静かで、本当に必要なときだけ鳴る。

## 全体像

```
        チャットで頼む／シートを直接書く
                     │
                     ▼
   ┌───────────────────────────────┐
   │  台帳（Google スプレッドシート）   │ ← 自分でも見る・直せる
   │  タスク／定例／受信箱／変更履歴    │
   └───────────────────────────────┘
        ▲                    │ 読む
        │ 書く（変更履歴つき）  ▼
   ┌───────────────┐   ┌──────────────────────┐
   │ AI（Claude）   │──▶│ 定期実行（クラウド）      │
   │ 書記・見張り番   │   │ 朝・夕・週次・月次        │
   └───────────────┘   └──────────────────────┘
        │                          │
        ▼                          ▼
  Google カレンダー ◀── 期日の通知を登録      スマホへのプッシュ（短い要約）
  （公式アプリで受け取る）
```

## 台帳の中身

| タブ | 役割 |
| --- | --- |
| タスク | 1行に1タスク。状態（未着手／進行中／完了／保留／中止）、区分、本文、期日、期日の種類（必達／頃／目安）、優先度、親ID、メモ、追加日・更新日・完了日、残り日数（数式） |
| 定例 | 毎月・毎週のルール。期日の何日前になったら今月分の行を作るかを書く |
| 受信箱 | 思いついたことを放り込む場所。週次レビューで振り分ける |
| 変更履歴 | AI が台帳を変えるたびに「いつ・どこを・変更前・変更後・理由」を1行残す。勝手な変更にすぐ気づけて、戻せる |

期限切れの行は赤、3日以内は橙で表示すると見落としにくい（条件付き書式）。

## 使い方

| やりたいこと | 方法 |
| --- | --- |
| 追加 | チャットで「11/5 までに〇〇」と頼む。またはシートに1行書く |
| 完了 | チャットで「〇〇終わった」。AI が候補の行を引用して「これですか？」と確認してから更新する |
| 一覧を見る | シートのフィルタ表示、またはチャットで「今週やることは？」 |
| 延期・中止 | チャットで伝えるか、シートを直接直す |

AI が守るルール:

1. **推測で完了にしない。**
2. 完了報告は、候補を引用して確認する。
3. 更新した行は、引用して報告する。
4. 変更のたびに変更履歴へ記録する。

## 定期実行（クラウドのスケジュールタスク）

手元のパソコンを開いていなくても動く。時刻は例で、自分に合わせて変える。数分ずれることがあるので、時刻が大事なものはカレンダーの通知に任せる。

| 時刻（例） | 内容 | 届け方 |
| --- | --- | --- |
| 毎朝 6:00 | **朝のまとめ**: 期限切れ、今日・明日の期日、最優先5件とその理由、今日の予定。7日以内になった定例の行を作り、14日以内に迫った重要な期日をカレンダーに登録する | プッシュ（先頭2行が本文） |
| 毎夕 17:30 | **夕方の棚卸し**: 今日の残りと明日の予定。変更はしない | プッシュ |
| 土曜 朝 | **週次レビュー**: 今週の完了と、期限切れ・停滞中のタスクを1件ずつ「日を決める／延期／やめる」で選ぶ形で出す | プッシュ＋スレッド |
| 毎月1日 | **月次の見通し**: 今月と来月の期日、定例、半年以内の大きな期日 | プッシュ |
| 毎週日曜 | **台帳のバックアップ**（任意）: スプレッドシートの写しを日付つきで保存 | 通知なし |

## 通知を絞る設計

通知が多いと、本当に大事なものが埋もれる。そのため次のようにする。

- **届ける時刻を決める**: 朝と夕方の2回が基本。ほかの時間は鳴らさない。
- **近づくほど段階的に上げる**: 期日の14日前=予告、7日前=今週の注意、3日前=要準備、前日と当日=最上位。順位は、期日の近さ・期日の種類・優先度・停滞日数・準備の重さから AI が判断する。
- **確実に鳴らしたい期日だけ**、Google カレンダーに通知つきで登録する。対象は、支払い・税・公的手続き・提出物・家族の約束・必達の期日など。件名の頭に `[期日]` を付け、前日の夕方と当日の朝にポップアップを出す。
- **まとめは短く、結論が先頭**: プッシュの本文は先頭の2行だけ読めば足りるようにする。
- **決める場面を作る**: 週次レビューで、期限切れと停滞を「日を決める／延期／やめる」のどれかに決着させる。放置されたタスクが通知を増やし続けるのを防ぐ。

## 準備するもの

人間が用意するもの（詳細は `LEDGER-PATTERN.md` と `SETUP.md`）:

1. 台帳のスプレッドシートと、編集者として共有したサービスアカウント。
2. クラウド環境のネットワークシークレット（サービスアカウントの鍵）。
3. 定期実行の作成（Claude の「スケジュールタスク」。朝・夕・週次・月次）。
4. 通知を受け取る公式の Google カレンダーアプリ（アプリによっては、Google 側で設定した通知が鳴らないことがある）。

## 注意

- 台帳に、給与明細・パスワード・他人の個人情報を書かない。
- 書き込みが `sheets.googleapis.com` で 403 になるときは、そのセッションが手元のパソコンに接続されている（Remote Control が有効）可能性がある。
- このリポジトリは公開。自分の台帳の ID、メール、実データ、他人の名前を書かない。
